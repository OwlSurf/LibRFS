# LibRFS — иллюстрированное описание

Кольцевая файловая система для внешней NOR-flash. Данные хранятся в **слотах** фиксированного размера; при заполнении буфера старые записи перезаписываются. Репозиторий: [OwlSurf/LibRFS](https://github.com/OwlSurf/LibRFS).

---

## 1. Зачем это нужно

```
┌─────────────────────────────────────────────────────────────┐
│  Микроконтроллер                                            │
│  ┌──────────────┐    add_slot_()   ┌─────────────────────┐  │
│  │  Приложение  │ ───────────────► │  LibRFS             │  │
│  │  (GPS, CAN…) │ ◄─────────────── │  (кольцевой буфер)  │  │
│  └──────────────┘   read_slot_()   └──────────┬──────────┘  │
│                                               │              │
│                                    erase / read / write      │
│                                               ▼              │
│                                    ┌─────────────────────┐    │
│                                    │  NOR flash          │    │
│                                    └─────────────────────┘    │
└─────────────────────────────────────────────────────────────┘
```

Журнал однородных записей, где важны последние N слотов, а не полная история.

## 2. Структура памяти

Память делится на **секторы** (единица erase) и **слоты** (единица записи).

```
  Пример: 512 КиБ, сектор 4 КиБ, слот 8 байт

  Сектор 0          Сектор 1          Сектор 2
  ┌────────────┐   ┌────────────┐   ┌────────────┐
  │ slot 0     │   │ slot 512   │   │ slot 1024  │
  │  …         │   │  …         │   │  …         │
  │ slot 511   │   │ slot 1023  │   │ slot 1535  │
  └────────────┘   └────────────┘   └────────────┘

  max_slots       = 65 536
  slots_per_sector = 512
  sectors          = 128
  max_data_slots   = 65 024   (один сектор — буфер под erase-ahead)
```

Последний байт слота — **статус чтения**: `0xFF` непрочитан, `0x00` прочитан. `add_slot_()` программирует только `slot_size - 1` байт payload.

<img alt="Архитектура — секторы и три указателя" src="images/ring-buffer-architecture.png" />

| Указатель | Поле | Назначение |
|-----------|------|------------|
| **W** | `slot_windex` | Куда пишется следующий слот |
| **R** | `slot_rindex` | Откуда читается следующий непрочитанный |
| **REC** | `slot_rec_index` | Самый старый ещё не discarded слот |

Индексы — `uint32_t`.

## 3. Операции

### Запись (`add_slot_`)

1. Программирует payload в слот W.
2. Увеличивает счётчики; при overflow сдвигает R и REC.
3. W += 1 (по кольцу).
4. Если W встал на границу сектора — **erase-ahead следующего сектора**.

### Чтение (`read_slot_`)

Читает FIFO, прожигает статус в `0x00`, двигает R.

### Recover (`recover_slot_`)

Двигает R назад. На NOR **нельзя** вернуть статус в `0xFF` без erase сектора. После reboot `em_init_()` снова увидит `0x00` и пропустит эти слоты, пока REC < R (их всё ещё можно recover в RAM, если не было второго сканирования после recover-без-перечитывания).

- Recover **после reboot** (без предварительного recover) работает: REC указывает на прочитанные-но-не-discarded, R — на первое unread.
- Recover **до reboot**, затем снова `em_init_()` — откат по RAM теряется, остаются flash-метки.

### Discard (`discard_slot_`)

Двигает REC вперёд. Когда REC проходит последний слот сектора, **этот** сектор стирается.

## 4. Переполнение

Когда записей больше `max_data_slots`, новые данные вытесняют самые старые непрочитанные.

## 5. Стирание секторов

```
  Сектор N+1 стирается, когда запись заполнила сектор N (erase-ahead).
  Сектор N стирается, когда discard подтвердил все его слоты.
```

Раньше индекс внутри сектора считался как `windex % sector_index` — erase почти никогда не вызывался, кроме ухода с сектора 0. Первый круг маскировался `em_reset_()`. Второй круг программировал NOR поверх старых битов (`AND`). Сейчас граница — `index % slots_per_sector == 0`.

---

## 6. Восстановление после reboot

Внешнее хранение индексов не используется. `em_init_()`:

1. Ищет переход «данные → пустой слот» — это **W**.
2. Если окно `[W - max_data_slots, W)` полностью занято — overflow, REC = начало окна.
3. Иначе REC — первый слот с данными, идя вперёд от W (пропуская дыру буфера / discarded).
4. R — первый непрочитанный слот в `[REC, W)`.
5. `slot_count` — число unread; `slot_rec_count` / `get_recover_count_()` — длина `[REC, R)`.

Payload (timestamp и т.п.) **не** разбирается.

```c
em_reset_(em);   /* первый запуск */
em_init_(em);    /* после перезагрузки */
```

## 7. Инициализация

```c
void *em = em_driver_init_(erase, read, write,
                           em_size, sector_size, slot_size, start_addr);
```

Колбэки типизированы (`uint32_t` адрес, `uint16_t` длина). Неверная геометрия или NULL-колбэк → `NULL`. Освобождение: `em_driver_deinit_(em)`.

| Параметр | distance (тесты) | track (тесты) |
|----------|------------------|---------------|
| `em_size` | 524 288 (512 КиБ) | 65 536 (64 КиБ) |
| `em_sector_size` | 4 096 | 4 096 |
| `em_slot_size` | 8 | 16 |
| `em_start_address` | 0x00000 | 0x80000 |

## 8. API

```c
add_slot_(em, data);
read_slot_(em, buf);
recover_slot_(em);
discard_slot_(em);
recover_all_slots_(em);
discard_all_slots_(em);
get_slot_count_(em);      /* unread R→W */
get_recover_count_(em);   /* окно REC→R */
em_driver_deinit_(em);
```

## 9. Ограничения

| Тема | Поведение |
|------|-----------|
| Порядок чтения | Строго FIFO |
| Потоки | Нет внутренней синхронизации |
| CRC | Нет |
| Ошибки flash | Колбэки без кода возврата |
| Recover vs NOR | Статус `0x00` нельзя поднять до `0xFF` без erase |
